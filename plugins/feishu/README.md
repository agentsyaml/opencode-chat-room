# Feishu channel adapter

Feishu/Lark adapter process for
[`@alexsun-top/chat-room-channeld`](https://www.npmjs.com/package/@alexsun-top/chat-room-channeld).
It speaks the adapter JSON-RPC contract, sends text/Markdown cards plus native
images and files, and optionally relays allowlisted group messages into a room.

## Run

The adapter is a generated typed single-file TypeScript program shipped inside
the root `@alexsun-top/opencode-chat-room` package; it is not published as its
own npm package. Build it from the repository root:

```sh
bun run build:adapter-feishu
```

This writes `plugins/feishu/dist/feishu-adapter.ts`: one file with no relative
imports and real TypeScript annotations. It is generated by concatenating the
typed modules under `plugins/feishu/src` without a bundler, so types are
preserved instead of erased. Node 22.18+ and 24 execute it directly through
native type stripping; it stays erasable-syntax-only: no `enum`, `namespace`, or
constructor parameter properties. Point the channeld account's
`adapter.command` at that file:

```yaml
accounts:
  - id: feishu-main
    platform: feishu
    adapter:
      command: ["node", "/opt/chatroom/feishu-adapter.ts"]
    env:
      FEISHU_APP_ID: cli_xxx
      FEISHU_APP_SECRET: xxx
      FEISHU_INBOUND: "1"          # optional
      FEISHU_INBOUND_CHATS: oc_xxx # required with inbound
```

Channeld appends `--experimental-transform-types` and
`--disable-warning=ExperimentalWarning` to the inherited `NODE_OPTIONS` of every
adapter child, so an uploaded `.ts` plugin may use `enum`, `namespace`, and
constructor parameter properties even though the generated Feishu adapter is
strip-safe. This
Node transform is experimental and bounded; the stable path is compiling the
adapter to a single `.js` file with a real TypeScript compiler. Adapter stdout
must stay protocol-only, with warnings and logs on stderr. The server process
itself stays strip-only.

Outbound attachments require the app permissions `im:resource:upload` and
`im:resource`. Inbound image/file messages are downloaded through the message
resource endpoint and imported into the chat-room's resource storage.

Limits: 10 MiB per image, 30 MiB per file. Failures are reported as receipts or
room notices; nothing is dropped silently.
